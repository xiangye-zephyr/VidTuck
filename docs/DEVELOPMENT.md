# VidTuck 开发与实现说明

Apple Silicon Mac 的本地视频下载工具。原生 AppKit 窗口、WKWebView 中文界面，后台通过独立子进程调用 yt-dlp、Deno、FFmpeg。应用无需 Node、Python 或 Homebrew，也无需运行本地服务器。

## 使用

1. 从 Releases 下载应用并复制到「应用程序」。当前为临时签名，未做 Developer ID 签名或苹果公证。
2. 在主窗口按 ⌘V 粘贴视频链接或分享文案，或直接拖入链接。支持一次加入多个链接，每次最多 50 个。默认自动解析并依次下载。
3. 底部「设置」可修改清晰度、视频/音频、保存目录，也可关闭自动下载。关闭后，点任务的三角按钮开始下载；双击空白区域可打开手动输入框。
4. 完成后点击「播放」或「显示文件」。全新安装默认目录为 `~/Downloads/VidTuck`；已有用户沿用原保存位置；更改目录只影响之后加入的任务。

最高 4K 表示清晰度上限，实际清晰度取决于网站、账号权限和返回的格式。在相同清晰度与帧率下，优先选择 H.264/AAC 以便 Mac 播放；默认优先合并为 MP4，其他编码可能保存为 MKV 并需要兼容播放器。音频导出为 M4A。任务可以暂停、继续，退出后保留记录。续传取决于网站是否仍提供相同媒体和引擎的分片支持；短期网页直链重启后需重新读取。

## 网站登录与网页辅助

支持 YouTube、B站、抖音和小红书。小红书已用两条有效完整视频分享链接完成本机下载验证；请保留 xsec_token 等链接参数。旧链接、参数失效或需要登录的视频仍可能失败，不能据此保证所有笔记或短链接都可用。站点解析受网站接口、网络、登录状态和链接有效期影响；不能保证每条视频都能下载。目前只完成开发者本机验证，其他设备上的兼容性仍待验证。

抖音粘贴后并行尝试直接读取分享页/详情接口与后台兼容解析，不弹出网页窗口。短链接一旦解析出目标 ID，后台页面即可直达视频详情，减少移动分享页跳转；页面在目标详情接口返回或站点 SDK 解出对应 JSON 时立即提取媒体地址，不必等待播放器渲染；没有取得接口数据时仍尝试目标播放器。拿到媒体就自动排队下载，封面缺失时在后台继续补齐，最多额外等待 12 秒，不阻塞下载。封面图片下载与缓存也在后台完成。所有媒体和接口封面均按目标视频 ID 匹配。后台页面静音，不读取推荐视频；后台解析最多 45 秒，失败后再尝试常规解析器。直接 HTTP 请求受平台限制时可能无法取得数据，不能保证完全省去后台网页解析；登录或验证仍可能需要人工操作。

0.2.6 针对抖音的起传等待做了两项调整：同一编码流优先选择站点返回的第一条直连 CDN 地址，重定向播放地址仍保留；下载开始连接后 5 秒仍未报告任何字节，且存在同一地址组、相同分辨率/码率/编码/大小的备用地址时，停止该次连接并切换一次。连接立即失败时同样最多切换一次；已收到数据、已暂停或已移除的任务不切换。该阈值从下载连接阶段开始计时，并非粘贴后 5 秒保证起传；没有对应镜像、解析慢或站点验证时仍可能等待更久。页面预热/复用试验收益不明确，未纳入发布版。

自动读取仍失败时点击任务的「网页辅助」，在独立窗口打开原视频。需要登录时由你本人完成，播放视频后点击「读取此页」。应用保存该平台在本应用内的 Cookie，再交给解析器重试；抖音、小红书还会尝试读取网页提供的媒体地址。网页媒体提取是实验功能，页面不提供可读地址时仍可能失败。YouTube 和 B站始终交给平台解析器配对音视频，避免网页辅助只取到无声画面。

网页辅助拥有独立网站数据，不读取 Safari、Chrome 或其他浏览器的账号。也可以在偏好设置中主动导入自己的 Netscape 格式 cookies.txt；导入只保留对应平台的域名。部分网站可能不允许内嵌浏览器登录，此时可用文件导入方式。

YouTube、B站和小红书首次解析得到的完整格式数据会临时保留，自动下载直接复用，省去下载前的第二次页面解析。修改清晰度仍从完整格式列表重新选择；缓存超过 10 分钟时重新读取，缓存地址下载失败时自动从原始链接重新解析一次。重启、移除或下载完成会清理对应的临时解析文件。

内置引擎优先使用官方 macOS 目录版，避免单文件版每次启动重新展开运行库造成的等待；同版本单文件版保留供更新使用。

偏好设置提供官方 yt-dlp nightly 更新。更新副本放在本应用的数据目录，不修改应用包。主动更新后优先使用更新副本；目前该副本为官方单文件版，其启动耗时可能与内置目录版不同。解析器更新期间暂停队列。

## 本机数据

- 为兼容改名前的数据，内部目录与 bundle ID 继续沿用原标识，已有任务、保存路径及本应用登录状态不迁移。
- 任务记录、平台 Cookie、更新后的解析器：`~/Library/Application Support/StreamNest/`
- 网页辅助的网站数据：macOS 为 `local.streamnest.mac` 分配的 WebKit 数据目录。
- 任务文件和 Cookie 权限为 0600；它们未额外加密，签名视频链接可能含短期访问参数，请勿把整个数据目录分享给他人。
- 「清除本地登录状态」清除本应用保存的 Cookie 和网页数据。「移除任务」只移除记录，保留视频；「清除已完成」同样保留文件。
- 无账号系统、无遥测、无云端上传；网络请求直接发往目标站点及其媒体服务，更新时请求官方 GitHub。浏览辅助页面自身的网络请求由相应网站决定。

## 从源码构建

需要 Apple Silicon Mac、macOS 15+、Xcode Command Line Tools，以及 FFmpeg 构建所需的 make、nasm、pkg-config 等工具。当前只构建 arm64，尚未实测 Intel 或较早 macOS。

```sh
zsh scripts/prepare-tools.sh
zsh scripts/build.sh
```

工具存放在源码目录 `.build-tools`，应用输出至源码文件夹的上一级。也可指定已准备好的工具目录：`zsh scripts/build.sh /绝对路径/tools`。图标已经附带；重新生成可运行 `swift scripts/make-icon.swift /tmp/VidTuck.iconset`，再用 `iconutil` 转为 icns。

主要文件：`Sources/Core.swift` 下载队列与引擎调用，`Sources/Douyin.swift` 目标视频数据解析与直接请求，`Resources/douyin-early.js` 提前读取目标详情响应，`Sources/App.swift` 原生窗口/登录/文件选择/网页辅助，`Sources/CoverStore.swift` 真实封面缓存，`Resources/index.html`、`app.css`、`app.js` 本地界面。

界面使用紧凑深色布局。任务条使用该视频元数据或目标视频页面提供的封面，裁切铺满并加暗色遮罩；封面无法取得时显示默认深色背景。不会替换为其他视频或示例图。封面转换为本地 JPEG，缓存在数据目录 `covers/`，进度更新复用图片。应用使用蓝青色图标，空列表水印为灰色。

`scripts/CoreTests.swift` 用本地 HTTP 媒体测试真实解析、文件下载、音频提取、错误处理、后台解析的成功/失败/暂停/移除和队列恢复。测试参数为隔离测试目录与工具目录，本地服务器固定使用 `127.0.0.1:18764`，需提供 `sample.mp4`。测试目录应每次新建，以避免历史状态影响。

`scripts/CoverTests.swift` 验证封面转码、进度重绘复用、重启缓存，以及无效地址/非图片/404 的默认背景。使用相同本地 HTTP 服务，额外提供 `cover-fixture.png`（可复制 `Resources/AppIcon.png` 作为仅测试用输入）。编译时同时加入 Core.swift、CoverStore.swift 和 Cocoa framework；第一个参数为全新的封面缓存目录。

`scripts/DouyinTests.swift` 验证目标 ID、播放地址筛选、清晰度、分享页 JSON，以及无封面立即交接、封面晚到不重置进度、暂停/移除后忽略迟到结果。编译时加入 Core.swift、Douyin.swift、CoverStore.swift、App.swift 和 Cocoa/WebKit framework，以全新的隔离测试目录为唯一参数。`scripts/DouyinEarlyTests.cjs` 是开发测试，验证网页原始 fetch/XHR 和 JSON.parse 返回值、reviver 与错误行为保留，只读取目标详情与排除其他响应；可用 Node 执行并将 `Resources/douyin-early.js` 路径作为参数。Node 仅供开发测试，不是应用运行依赖。

`scripts/CacheTests.swift` 验证解析结果复用、0600 权限、重启与移除清理、过期缓存更新、失效地址自动重新解析、真实 M4A 提取，以及缓存最高画质后改选 480p。与 CoreTests 一样编译并传入全新隔离目录和工具目录，使用相同本地 HTTP 媒体服务。

`scripts/DouyinTransferTests.swift` 用真实引擎验证慢首字节和 HTTP 失败时的同画质镜像切换，以及暂停/移除后不重试。先运行 `python3 scripts/DelayFixture.py /包含sample.mp4的测试目录`，监听仅本机的 `127.0.0.1:18766`；将 Core.swift 与该测试编译后，传入新的隔离测试目录和工具目录。

## REA 与来源

使用 [REA](https://github.com/morluto/rea) 的 `inspect-artifact` 对本机 Downie 应用包做了只读静态清单检查。REA 没有恢复下载算法或原始源码。VidTuck 的下载逻辑与界面代码独立实现，不包含 Downie 的程序或站点脚本。界面参考 Downie 4 的紧凑任务列表交互，VidTuck 是独立项目，与 Downie 无关联。

本项目自身源码采用 MIT 许可。第三方程序的许可、来源和 FFmpeg 对应源码见 `ThirdParty/`。REA 是开发时的调查工具，不是运行依赖。
